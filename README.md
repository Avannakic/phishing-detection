# Генерация и фильтрация LLM-синтетики для детекции русскоязычного фишинга

Официальный репозиторий пайплайна генерации синтетических данных и подготовки выборок к исследованию по обнаружению фишинговых атак в мессенджерах на базе трансформеров (`DeepPavlov/rubert-base-cased`).

---

## 1. Постановка задачи и схема разметки классов

Данные размечены на **3 непересекающихся класса** для разделения бытового общения, коммерческого спама и целевых социоинженерных атак:
- **`0` (Legitimate / Ham):** Легитимные пользовательские сообщения и информационные сводки.
- **`1` (Spam):** Массовая коммерческая рассылка, навязчивая реклама товаров/услуг и серые офферы без прямой попытки кражи учетных данных или средств получателя.
- **`2` (Phishing):** Целевые фишинговые атаки социальной инженерии (выманивание кодов авторизации, учетных данных, переводы на «безопасные счета», переход на фишинговые ресурсы и вредоносные боты).

Реальный корпус фишинга ($N = 300$, `real_phishing.csv`) собран методом OSINT из верифицированных сводок по кибербезопасности: из публикаций извлекались исключительно прямые цитаты реальных мошеннических сообщений без сопутствующего журналистского контекста.

---

## 2. Метод генерации и параметрический промптинг

Генерация синтетических фишинговых сообщений выполнялась в режиме **zero-shot** (без подачи реальных примеров из тестового набора в промпт, что исключает прямое копирование) с помощью локальной языковой модели **`llama3` (Meta Llama 3 8B Instruct, квантование `Q4_0`)** через фреймворк **Ollama** при температуре **`temperature = 0.8`**.

Для обеспечения высокого лексического и структурного разнообразия вместо статического промпта использовалась **комбинаторная матрица параметрических промптов** в две итерации:
1. **Базовая генерация (`01_generate_base_phishing.py`):** 10 типовых ролей отправителей (Госуслуги, ЦБ РФ/ФСБ, ректорат/деканат, крупные банки, родственники/знакомые, поликлиника, официальная поддержка Telegram, боты с бесплатным Telegram Premium, боты знакомств/18+, магазины ключей Steam/нейросетей) × 2–3 психологические тактики манипуляции (давление авторитетом, страх блокировки/уголовной ответственности, жадность, срочность).
2. **Целевая догенерация сложных случаев (`02_generate_targeted_addition.py`):** Фокусное расширение 6 сценариев, мимикрирующих под рекламный спам (банковский кешбэк, голосования в конкурсах, крипто-чеки с раздачей средств, токены для ChatGPT, сливы 18+).

### Генерация фоновых классов для чисто синтетической модели (`00_generate_ham_and_spam.py`)
Для обучения «Модели 2» (Synthetic Only) без участия реальных данных с помощью той же модели `llama3` (`temperature = 0.8`) были сгенерированы фоновые корпуса:
- **Синтетический Ham (`label = 0`, 10 000 сообщений):** бытовые диалоги в мессенджерах, рабочая переписка, обсуждение новостей и короткие повседневные реплики без коммерческих предложений и подозрительных ссылок.
- **Синтетический Spam (`label = 1`, 10 000 сообщений):** массовые рекламные рассылки (маркетплейсы, скидки, промокоды, инфобизнес, вакансии удаленной работы, реклама Telegram-каналов) без социоинженерного выманивания паролей, кодов авторизации или переводов средств.

### Управляемые параметры внутри шаблона промпта:
- **Градация длины текста (`ALLOWED_LENGTHS`):** 
  * *Короткие:* 1–2 предложения (до 150 символов) — пакетная генерация по 10 шт.
  * *Средние:* 3–5 предложений (до 300 символов) — по 4 шт.
  * *Длинные:* развернутый текст (500–700 символов) — по 2 шт.
- **Вероятностный контроль эмодзи (`EMOJI_RULES`):** Индивидуальная вероятность использования эмодзи в зависимости от профиля отправителя — от `1–2%` («Пиши СТРОГО БЕЗ эмодзи, сухой канцелярский язык») для имитации Госуслуг и силовых ведомств до `80–90%` обильных кликбейтных эмодзи для мошеннических ботов.
- **Баланс наличия ссылок:** 50% вероятности органичной вставки URL-адреса против 50% текстового призыва к действию без ссылки.

## 3. Очистка, процедурная обработка и сборка датасетов

Весь цикл от генерации до формирования готовых для обучения выборок автоматизирован. Пайплайн включает следующие этапы:

- **Шаг 3: Очистка и фильтрация (`03_clean_and_filter.py`)** 
  Удаление строк с артефактами LLM («я не могу», «as an AI», «вот сгенерированные сообщения»), фильтрация по длине, количеству кириллических символов и очистка от Markdown-разметки.
- **Шаг 4: Слияние пулов (`04_merge_synthetic_pools.py`)**
  Дедупликация и объединение базовых и целевых генераций в единый датафрейм.
- **Шаг 5: Процедурная генерация URL (`05_procedural_urls.py`)**
  Замена плейсхолдеров (вида `example.com` или `[ссылка]`) на случайно сгенерированные правдоподобные URL-адреса и домены с использованием регулярных выражений.
- **Шаг 6: Сборка выборок и Data Leakage Prevention (`06_build_training_datasets.py`)**
  Финальное формирование трех типов обучающих датасетов (Real Only, Synthetic Only, Hybrid). 
  
**Особое внимание уделено защите от утечек данных (Data Leakage):**
Единый файл с реальным фишингом (`real_phishing.csv`) строго делится на две части: 80% уходит в обучение (гибридное и реальное), а 20% откладывается в изолированный файл **`rubert_test_final.csv`**. 
Перед добавлением синтетического фишинга в обучающие выборки он проходит проверку на косинусное сходство (Cosine Similarity) с тестовой выборкой с помощью `TF-IDF` на униграммах и биграммах. Любые синтетические тексты со сходством >= 0.85 с реальным тестом безвозвратно удаляются.

## 4. Структура проекта

Проект организован с изоляцией исходных, промежуточных и финальных данных:

```text
phishing-detection/
├── data/
│   ├── interim/           # Временные файлы и сырая сгенерированная синтетика
│   ├── processed/         # Готовые финальные датасеты для обучения моделей
│   │   ├── rubert_test_final.csv
│   │   ├── rubert_train_hybrid_final.csv
│   │   ├── rubert_train_real_final.csv
│   │   └── rubert_train_synth_final.csv
│   └── real/              # Исходные реальные данные (Ham, Spam, Phishing)
├── src/
│   └── data_generation/   # Скрипты конвейера генерации и обработки
│       ├── 00_generate_ham_and_spam.py
│       ├── 01_generate_base_phishing.py
│       ├── 02_generate_targeted_addition.py
│       ├── 03_clean_and_filter.py
│       ├── 04_merge_synthetic_pools.py
│       ├── 05_procedural_urls.py
│       └── 06_build_training_datasets.py
├── .gitignore             # Исключение .venv, кэша и промежуточных CSV
├── README.md
├── requirements.txt
└── run_pipeline.py        # Мастер-скрипт для последовательного запуска всего конвейера
```

## 5. Установка и запуск пайплайна

### Требования
1. Установленный Python 3.9+
2. Установленный локальный сервер [Ollama](https://ollama.com/) с загруженной моделью `llama3`:
   ```bash
   ollama pull llama3
   ```

### Быстрый старт
1. Клонируйте репозиторий и создайте виртуальное окружение:
   ```bash
   python -m venv .venv
   source .venv/Scripts/activate  # Для Windows (Git Bash)
   # source .venv/bin/activate    # Для Linux/macOS
   ```
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Поместите исходные реальные данные (`real_ham.csv`, `real_spam.csv`, `real_phishing.csv`) в папку `data/real/`.
4. Запустите полный цикл генерации и обработки:
   ```bash
   python run_pipeline.py
   ```
   *(Пайплайн поддерживает чекпоинты. При прерывании `Ctrl+C` накопленные строки сохраняются, и при повторном запуске генерация продолжится с места остановки).*

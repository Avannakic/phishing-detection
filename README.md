# Детекция русскоязычного фишинга: синтетические данные, QLoRA и Few-Shot

Исследовательский пайплайн для классификации сообщений мессенджеров на три непересекающихся класса:

- `0` — легитимное сообщение (**Ham**);
- `1` — коммерческий спам (**Spam**);
- `2` — фишинг и социальная инженерия (**Phishing**).

Репозиторий объединяет генерацию русскоязычной синтетики через Ollama, очистку и предотвращение утечек данных, 5-фолдовую кросс-валидацию классических энкодеров и генеративных LLM с 4-bit QLoRA, а также Zero-Shot/Few-Shot оценку LLM без дообучения.

## 1. Пулы данных

Во всех CSV обязательна колонка `message`; на шаге 06 колонка `label` устанавливается заново по классу. Кодировка — UTF-8.

| Пул | Файл в `data/processed/` | Размер |
|---|---|---:|
| Реальный Ham | `real_ham.csv` | 20 000 |
| Реальный Spam | `real_spam.csv` | 20 000 |
| Реальный Phishing | `real_phishing.csv` | 300 |
| Синтетический Ham | `synthetic_ham.csv` | 14 000 |
| Синтетический Spam | `synthetic_spam.csv` | 14 000 |
| Синтетический Phishing | `final_synthetic_phishing.csv` | 10 000 |

Исходные реальные пулы размещаются в `data/real/` под теми же именами. Сырые и промежуточные синтетические данные находятся в `data/interim/`.

Шаг 06 нормализует пробелы, удаляет пустые строки и точные дубликаты без учёта регистра, выравнивает пулы до целевых размеров и сохраняет все шесть файлов в `data/processed/`. Синтетический фишинг дополнительно сравнивается **со всеми 300 реальными фишинговыми сообщениями**:

1. удаляются точные совпадения;
2. удаляются нечёткие дубликаты с TF-IDF cosine similarity строго `> 0.85`, `ngram_range=(1, 2)`.

Если после очистки какого-либо пула недостаточно строк, шаг 06 завершается с ошибкой, а не незаметно уменьшает исследовательскую выборку. Статический `test_final.csv` не создаётся: Test/Val/Train формируются заново в каждом фолде.

## 2. Генерация синтетики: Qwen3-14B и fallback на VIKHR

Шаги 00–02 используют локальный Ollama, основную модель **`qwen3:14b`** и `temperature = 0.8`. В начале каждого скрипта настраивается `FALLBACK_MODEL = "vikhr-llama3.1-8b"`.

Детектор отказов проверяет короткие ответы и маркеры отказов (`я не могу`, `извините`, `как ии`, `не могу помочь`, `мошеннич`, `незаконн`, `as an ai`, `i cannot`). Отслеживаются:

- доля отказов в заполненном скользящем окне последних 20 запросов — переключение при значении строго выше 65%;
- три полных отказа подряд — немедленное переключение.

После срабатывания выводится предупреждение и генерация продолжается с VIKHR. Промежуточные чекпоинты сохраняются; при повторном запуске накопленные сообщения загружаются из них.

Целевые объёмы генерации:

- 14 000 Ham и 14 000 Spam на шаге 00;
- 14 000 базовых фишинговых сообщений на шаге 01;
- 6 000 целевых фишинговых сообщений на шаге 02.

Запас в 20 000 сырых фишинговых сообщений предназначен для последующей фильтрации, дедупликации, процедурной замены URL и удаления утечек до 10 000 чистых примеров.

Промпты варьируют отправителя, тактику социальной инженерии, длину, стиль, эмодзи и наличие ссылки. Генерация выполняется без подачи реальных фишинговых примеров.

Шаги 00–06 можно запустить через оркестратор:


## 4. Мультимодельная кросс-валидация и QLoRA

Шаг 07 поддерживает четыре архитектуры:

| Ключ | Hugging Face ID | Режим | Batch | Grad. accum. | LR |
|---|---|---|---:|---:|---:|
| `RuBERT` | `DeepPavlov/rubert-base-cased` | Полное дообучение энкодера | 64 | 1 | 2e-5 |
| `RuRoBERTa-large` | `ai-forever/ruRoberta-large` | Полное дообучение энкодера | 32 | 2 | 1e-5 |
| `Vikhr` | `Vikhrmodels/Vikhr-Llama-3.1-8B-Instruct` | 4-bit QLoRA | 8 | 8 | 1e-4 |
| `Qwen3-14B` | `Qwen/Qwen3-14B` | 4-bit QLoRA | 8 | 8 | 1e-4 |

Для LLM применяются `BitsAndBytesConfig` с 4-bit NF4, двойным квантованием и `bfloat16`, `prepare_model_for_kbit_training` и LoRA с `r=16`, `alpha=32`, `dropout=0.05`. Адаптеры подключаются к `q_proj`, `k_proj`, `v_proj`, `o_proj`; классификационная голова `score` сохраняется в обучаемых модулях. Используется `AutoModelForSequenceClassification` с тремя метками.

Общие параметры: 3 эпохи, `max_length=256`, 150 warmup steps, `weight_decay=0.01`, выбор лучшего чекпоинта по `f1_macro`, один сохраняемый чекпоинт. Полный запуск выполняет 160 обучающих прогонов: 4 модели × 8 экспериментов × 5 фолдов.

### Разбиение в каждом фолде

`StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` применяется к 300 реальным фишинговым сообщениям. Для фолда используется `seed = 42 + fold`:

- реальные Ham и Spam независимо перемешиваются и без пересечений делятся на 14 000 Train, 3 000 Val и 3 000 Test для каждого класса;
- 60 реальных фишинговых сообщений образуют слепой Test, оставшиеся 240 делятся на 200 Train и 40 Val;
- из 10 000 синтетических фишинговых сообщений сначала выделяется валидационный резерв до 1 000 примеров; оставшиеся 9 000 доступны для Train.

Внутри фолда все модели и эксперименты получают одинаковые реальные Train/Val/Test. Шаг 08 повторяет этот алгоритм с теми же seed, поэтому его тестовые наборы совпадают с шагом 07.

`VAL_SYNTH_PHISH_MODE` управляет валидацией:

- `pure_synth_only` (по умолчанию) — в `4_Model2_PureSynthetic` 40 реальных фишинговых Val-примеров заменяются резервом синтетики; Val остальных экспериментов полностью реальный;
- `always_include_synth` — синтетический резерв также добавляется к Val гибридных экспериментов 5–8.

### Восемь экспериментов

1. `1_Baseline_Imbalanced` — реальные 14k Ham + 14k Spam + 200 Phishing.
2. `2_Baseline_ClassWeights` — те же данные, вес фишинга в CrossEntropy равен `len(real_ham_train) / len(real_phish_train)`.
3. `3_Baseline_Oversampling` — случайное дублирование 200 реальных фишинговых Train-примеров до 7 000.
4. `4_Model2_PureSynthetic` — 14k синтетических Ham + 14k Spam + 7k Phishing.
5. `5_Model3_Hybrid_Full_100pct` — реальные фоновые классы + 200 реальных и 6 800 синтетических Phishing.
6. `6_Ablation_Hybrid_50pct` — 200 реальных и 3 400 синтетических Phishing.
7. `7_Ablation_Hybrid_25pct` — 200 реальных и 1 700 синтетических Phishing.
8. `8_Ablation_Hybrid_10pct` — 200 реальных и 680 синтетических Phishing.

Запуск всех моделей и экспериментов:

```bash
python src/07_train_rubert_and_results.py
```

Можно ограничить запуск, например:

```bash
python src/07_train_rubert_and_results.py \
  --models RuBERT RuRoBERTa-large \
  --experiments 1_Baseline_Imbalanced 4_Model2_PureSynthetic \
  --val-synth-phish-mode pure_synth_only
```

Результаты сохраняются в `results/`:

- `folds_{model_key}_{exp_name}.csv` — метрики каждого из пяти фолдов;
- `SUMMARY.csv` — единая таблица с `Model`, `Experiment`, `CM_Sum_All_Folds` и `mean ± std (CI: ±ci95)` по t-распределению Стьюдента;
- `checkpoints/` — чекпоинты Trainer.

## 5. Zero-Shot и Few-Shot оценка LLM

Шаг 08 оценивает Qwen3-14B и VIKHR как генеративные классификаторы в 4-bit, **без обновления весов**. Поддерживаются режимы:

- `Zero-Shot` — только инструкция и классифицируемое сообщение;
- `Few-Shot_Real` — по 3 случайных примера Ham, Spam и реального Phishing из Train текущего фолда;
- `Few-Shot_Synth` — по 3 примера каждого класса, но Phishing берётся из синтетического Train-пула после отделения валидационного резерва.

Модель должна вернуть `0`, `1` или `2`. Скрипт парсит ответ, считает accuracy, macro-F1, precision/recall/F1 фишинга и сохраняет сырые ответы для аудита. Нераспознанные ответы считаются ошибочными предсказаниями и отдельно отражаются в колонке `unparsed`.

```bash
python src/08_llm_few_shot_cv.py
# Или только один режим:
python src/08_llm_few_shot_cv.py --models Qwen3-14B --modes Few-Shot_Real
```

В `results_few_shot/` записываются `folds_{model_key}_{mode}.csv`, `predictions_*.csv` и `SUMMARY_FEW_SHOT.csv` со схемой сводки, совместимой с `SUMMARY.csv`.

## 6. Установка

Требуются Python 3.9+ и локальный Ollama для генерации. Для 4-bit QLoRA/Few-Shot практически необходим CUDA GPU с достаточным объёмом VRAM; полный запуск всех конфигураций ресурсоёмок.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

ollama pull qwen3:14b
# Модель с именем FALLBACK_MODEL также должна быть доступна в локальном Ollama:
ollama pull vikhr-llama3.1-8b
```

При первом запуске шагов 07–08 Hugging Face загружает выбранные модели, если их нет в кэше. Зависимости включают `peft`, `bitsandbytes`, `sentencepiece` и `protobuf`; версия Transformers должна поддерживать Qwen3.

Минимальная статическая проверка:

```bash
python -m compileall -q run_pipeline.py src
```

Полная проверка требует реальных CSV, локальных генеративных моделей и вычислительных ресурсов. Автоматических тестов и CI в репозитории нет.
